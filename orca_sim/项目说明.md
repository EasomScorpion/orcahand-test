## 1. 项目定位

`orca_sim` 是 [ORCA Hand](https://www.orcahand.com) 灵巧手的仿真环境，遵循 [Gymnasium](https://gymnasium.farama.org/) 接口规范，使用 [MuJoCo](https://mujoco.readthedocs.io/) 作为物理引擎与渲染后端。它提供的核心能力：

- **Gymnasium 风格的环境**：`reset / step / render / close`，兼容所有主流 RL/IL 工具链（Stable-Baselines3、RLlib、CleanRL、Imitation……）。
- **多种手型与版本**：左手、右手、双手组合，以及每种手型的「标准版」与「扩展版（含 U2D2 板、相机支架、风扇等附加结构）」。
- **多代硬件版本**：通过 `version="v1" / "v2"` 切换，同一代号下场景/模型文件是兼容的。
- **可扩展任务骨架**：内置一个 `OrcaHandRightCubeOrientation` 任务（手内翻立方体使红面朝上），可作为二次开发新任务的参考模板。

依赖（来自 `pyproject.toml`）：

```
gymnasium >= 0.29
mujoco    >= 3.1
numpy     >= 1.26
Python    >= 3.10
```

## 3. 运行环境与安装

```bash
# 推荐 Python 3.11
uv venv orca --python 3.11
source orca/bin/activate
uv pip install orca_sim            # 装 PyPI 稳定版
# 或
uv pip install -e .                # 本仓库源码安装（开发推荐）
```

第一次构建时 `pyproject.toml` 中 `[tool.setuptools.package-data]` 会把所有 XML/MJCF/STL 资产打包进 wheel，因此安装完后可直接 `import orca_sim`。

最小可运行示例（与 `random_policy.py` 等价）：

```python
from orca_sim import OrcaHandRight

env = OrcaHandRight(render_mode="human")
obs, info = env.reset(seed=0)
print(env.action_space)            # Box(17,)
for _ in range(200):
    obs, reward, term, trunc, info = env.step(env.action_space.sample())
    if term or trunc:
        obs, info = env.reset()
env.close()
```

`random_policy.py` 还提供 CLI：

```bash
python random_policy.py --env combined_extended --version v2 --render-mode human --steps 1000
```

`--env` 可选：`left / left_extended / right / right_extended / right_cube_orientation / combined / combined_extended`。

### 3.1 常用启动命令速查

```bash
# 先激活 venv（Windows bash；Linux/macOS 用 source orca/bin/activate）
source orca/Scripts/activate

# === view_v1.py：v1 专用快速查看器（static/demo/random 三种模式） ===
```

## 4. 环境分层结构（最重要的一节）

### 4.1 类层次

`src/orca_sim/envs.py` 定义：

```
BaseOrcaHandEnv(gym.Env[np.ndarray, np.ndarray])
    ├── OrcaHandLeft            → scene_left.xml
    ├── OrcaHandRight           → scene_right.xml
    ├── OrcaHandCombined        → scene_left.xml + scene_right.xml
    ├── OrcaHandLeftExtended    → scene_left_extended.xml
    ├── OrcaHandRightExtended   → scene_right_extended.xml
    └── OrcaHandCombinedExtended→ scene_combined_extended.xml

OrcaHandRightCubeOrientation(BaseOrcaHandEnv)   # 在 task_envs.py
```

`BaseOrcaHandEnv` 做的事情：

1. 解析 `scene_file + version`，调用 `versions.resolve_scene_path()` 拿到绝对路径；
2. 用 `mujoco.MjModel.from_xml_path` 加载模型，构造 `MjData`；
3. 根据 `model.actuator_ctrlrange` 动态生成 `action_space = Box(low, high)`（**每个关节的目标角度，弧度**）；
4. `observation_space = Box(-inf, inf, shape=qpos+qvel)`；
5. `step(action)`：把 action clip 到 `ctrlrange`，调用 `mj_step(model, data, nstep=frame_skip)`（默认 `frame_skip=5`），再读 `qpos`、`qvel` 作为 obs；
6. `render()` 支持两种模式：
   - `"rgb_array"`：返回 `mujoco.Renderer` 离屏渲染的图像；
   - `"human"`：用 `mujoco.viewer.launch_passive` 弹出被动查看器（首次启动时强制使用 MJCF 默认 free camera）。

`_get_obs / _get_reward / _get_terminated / _get_truncated / _get_info` 都设成可被子类覆盖的钩子，纯「裸手」环境里它们返回 `qpos+qvel / 0 / False / False / {}`。

### 4.2 版本管理（`versions.py`）

```python
LATEST_VERSION = "v2"
SCENES_ROOT = PACKAGE_ROOT / "scenes"
```

- `list_versions()`：扫 `scenes/` 下含 `scene_left.xml` 的子目录，按 `vN` 数字排序。
- `latest_version()`：必须是已发现的版本之一；否则报错。
- `resolve_version(v)`：`None` → latest；否则必须存在于已发现集合里。
- `resolve_scene_path(scene_file, version=None)`：先按指定 `version`；否则按 `_scene_resolution_order()`（`LATEST_VERSION` 在前，其余倒序）逐个查找 `scenes/<v>/<scene_file>`，找不到抛 `FileNotFoundError`。

所以「`OrcaHandRight()` 默认就是 v2」。需要回退到老硬件时显式写 `OrcaHandRight(version="v1")`。

### 4.3 Gymnasium 注册（`registry.py`）

`register_envs()` 会枚举 `list_versions()` × 7 个场景，组合出形如 `OrcaHandLeft-v1` / `OrcaHandRightCubeOrientation-v2` 的 `env_id`，写入 `gym.registry`。调用后即可 `gym.make("OrcaHandRight-v2")`。

注意 `OrcaHandRightCubeOrientation` 目前只在 `scene_right_cube_orientation.xml` 存在时才会被注册（即 v1、v2 都有），详见 `test_registry.py`。

### 4.4 资产布局

#### v1
- `scenes/v1/scene.xml`：地面、灯光、相机参数（**只**包含世界几何/视觉，不放机器人）。
- `scenes/v1/scene_*.xml`：用一个或多个 `<include file="../../models/v1/...mjcf"/>` 把机器人拼进场景。
- `models/v1/*.mjcf`：完整的左手 / 右手 MJCF，自带 `<worldbody>`、`<actuator>`、`<contact>`，包含 `*_extended`（多 6 个 mesh：fans/u2d2/camera_mount）和 `right_cube_orientation`（额外嵌入 task cube）。
- STL 资源在 `models/v1/assets/mjcf/{left,right}/{visual,collision}/*.stl`。

#### v2
- `models/v2/assets/scene.xml` / `options.xml`：分别承担 v1 `scenes/v1/scene.xml` 的角色（场景 + 材质/joint 默认值）。
- `models/v2/mjcf/orcahand_left.mjcf`、`orcahand_right.mjcf`：v2 把 actuator 与 contact 拆分到这两个文件，它们在 v2 里**不带** `<worldbody>`——只声明资产和执行器。
- `models/v2/mjcf/orcahand_{left,right}_body.xml`：纯 `<worldbody>` 树，定义 kinematic 链与 mesh。
- v2 场景文件（`scenes/v2/scene_*.xml`）按以下顺序组装：

```xml
<include file="../../models/v2/assets/scene.xml"/>
<include file="../../models/v2/assets/options.xml"/>
<include file="../../models/v2/mjcf/orcahand_{left,right}.mjcf"/>   <!-- asset + actuator -->
<worldbody>
  <body name="(left|right)_mount" pos="..." euler="...">
    <include file="../../models/v2/mjcf/orcahand_{left,right}_body.xml"/>
  </body>
</worldbody>
```

也就是说 v2 把「世界/灯光/资产/执行器」与「机器人运动链」解耦了，方便同时插入两只手和重新打 mount 位姿。

## 5. 机器人结构（关节与执行器）

无论 v1 还是 v2，每只手都有 **17 个 `position` 类型的执行器**（即控制目标是目标关节角；`forcerange="±1 N·m"`，`kp=2.0`），与 17 个 hinge 关节一一对应。这是 `tests/test_envs.py` 中 `action_size=17` 的来源。

| 模块 | 关节 | 说明 |
|---|---|---|
| 基座 | `*_wrist` | 腕关节（绕 X 轴屈伸） |
| 拇指 (T) | `*_thumb_mcp`, `*_thumb_abd` (v2 中叫 `*_t-cmc`, `*_t-abd`), `*_thumb_pip`, `*_thumb_dip` (v2 `*_t-mcp`, `*_t-pip`) | CMC 外展/内收 + MCP 屈伸 + PIP/DIP 联动 |
| 食指 (I) | `*_index_abd`, `*_index_mcp`, `*_index_pip` | 外展 + MCP + PIP |
| 中指 (M) | `*_middle_abd`, `*_middle_mcp`, `*_middle_pip` | 外展 + MCP + PIP |
| 无名指 (R) | `*_ring_abd`, `*_ring_mcp`, `*_ring_pip` | 外展 + MCP + PIP |
| 小指 (P) | `*_pinky_abd`, `*_pinky_mcp`, `*_pinky_pip` | 外展 + MCP + PIP |

每根手指 3 自由度 + 拇指 4 自由度 = 16，再加腕关节 = 17。

> 命名差异：v1 用 `*_thumb_mcp / *_thumb_abd / *_thumb_pip / *_thumb_dip`；v2 改为更符合解剖学的 `*_t-cmc / *_t-abd / *_t-mcp / *_t-pip`。`action_space` 是按 `model.actuator_trnid` 顺序取的，所以即使关节名字换了，行为是一致的——但写策略/可视化代码时请记得按版本区分关节名。

「Extended」版本额外渲染/碰撞 6 个部件：`tower_main / tower_hull / tower_text` 是基础配置就有的；扩展版再叠加 `tower_fans / tower_u2d2 / tower_camera`，使整只手外观上更接近带外壳的实物。

`contact` 段对相邻手指段做 `<exclude>`，避免自碰导致接触求解爆炸。`_extended` 拷贝自同一份 contact 规则。

## 6. 观察 / 动作 / 复位

### 6.1 观测

基础环境（`BaseOrcaHandEnv._get_obs`）：

```
obs = concat( qpos , qvel )        # shape = (nq + nv,)
```

单手 `nq=nv=17`，双手（`OrcaHandCombined*`）`nq=nv=34`，因此测试断言里 `obs_size` 分别是 `34` 与 `68`。

### 6.2 动作

```python
action_space = Box( low=model.actuator_ctrlrange[:, 0],
                    high=model.actuator_ctrlrange[:, 1],
                    dtype=float32 )
```

每一步 `step` 内部会把传入 action clip 到 `ctrlrange` 再写入 `data.ctrl`；超过 `frame_skip=5` 步的物理子步也会用同一个 ctrl，所以动作等价于「目标关节角度」。

### 6.3 复位

`reset(seed=None, options=None)`：

1. 调用父类 `gym.Env.reset(seed=seed)`（让 `np_random` 可复现）；
2. `mujoco.mj_resetData(model, data)`；
3. 若 `options["qpos"]` / `options["qvel"]` 给出完整向量则整体覆盖，否则用默认值；
4. `mj_forward` 一次，更新派生量；
5. 若 `render_mode=="human"`，立即调一次 `render()`。

### 6.4 渲染

- `render_mode` 必须是 `None / "human" / "rgb_array"`，否则 `ValueError`。
- `"rgb_array"`：懒创建 `mujoco.Renderer(model)`，每次 `render()` 返回一张 `H×W×3` 的 `np.uint8` 帧。
- `"human"`：懒创建 `mujoco.viewer.launch_passive(model, data)`，并在首次启动时执行 `mujoco.mjv_defaultFreeCamera(model, viewer.cam)` 让视角回到 MJCF 默认；后续调用 `viewer.sync()`。**macOS 上需用 `mjpython`** 而非 `python`（见 `envs.py:140` 的提示）。

> 提示：MuJoCo 文档约定 `frame_skip=5` 等价于「动作持续 5×`mj_step` 子步」，默认时间步长 2 ms，所以每个 env 步进 ≈ 10 ms，对应 `metadata["render_fps"]=30` 时的 33 ms 间隔，刚好留出渲染余量。

## 7. 任务示例：`OrcaHandRightCubeOrientation`

文件：`src/orca_sim/task_envs.py`，继承自 `BaseOrcaHandEnv`。

### 7.1 场景差异

相比 `scene_right.xml`，`scene_right_cube_orientation.xml` 在 `<worldbody>` 里多塞了一个 `task_cube` 自由体：

- 位置 `(0.17, -0.015, 0.19)`、姿态 `(0, 1, 0, 0)`（v2 中是 `quat="0 0.70710678 0.70710678 0"`，让红面朝下）；
- 质量 80 g，惯性对角 `1.73e-5`；
- `task_cube_body` 是一个 36 mm 见方的米色 box，`friction="1.2 0.01 0.002"`；
- `task_cube_red_face` 是一层薄板（`pos="0 0 0.0192"`）贴合 +Z 面，红色 (`rgba=0.92 0.10 0.08`)，`contype=0 conaffinity=0` —— **不参与碰撞，仅作视觉标记**；
- 通过 `cube_freejoint`（6-DoF free joint）挂在 worldbody 下，可自由飞行/旋转。

v2 场景把右手的 mount 旋转到 `quat="0 0.70710678 0.70710678 0"`，相当于把整只手翻成「手掌朝上」姿态，cube 直接放在掌心上方。

### 7.2 观测、奖励、终止条件

- `_get_obs`：在基础 `qpos||qvel` 后面追加
  - `red_face_world_normal` (3)：把 `+Z_local` 通过 cube 的当前四元数旋转到世界系；
  - `red_face_up_alignment` (1)：上面的法向量与世界 `+Z` 的点积。
  
  因此 `obs_size = 34 + 4 = 38`？实际 `OrcaHandRightCubeOrientation-v2` 的 obs 为 `51`。差额来自 cube 的 `qpos`（7 = pos3 + quat4）和 `qvel`（6）以及额外 4 项 ⇒ `34 + 7 + 6 + 4 = 51`。注意：`qpos / qvel` 现在涵盖 cube 自由度，所以 cube 状态已经隐含在 obs 前段。

- `_get_reward`：

```
reward = 0.5 * (alignment + 1)             # 对齐奖励 ∈ [0, 1]
       + 0.10 * clip(z_cube - 0.12, 0, 0.12) / 0.12   # 抬起 bonus
       - (1.0 if cube.z < 0.05 else 0.0)              # 掉落惩罚
```

- `_get_terminated`：
  - 成功：`alignment ≥ cos(15°) ≈ 0.9659`（默认 `success_tolerance_rad=15°`）；
  - 失败：cube z 坐标低于 `drop_height` (默认 5 cm)。
- `_get_truncated`：`elapsed_steps >= max_episode_steps`（默认 200）。

### 7.3 复位选项

构造参数：

| 参数 | 含义 | 默认 |
|---|---|---|
| `scene_file` | MJCF 场景文件 | `scene_right_cube_orientation.xml` |
| `cube_joint_name` / `cube_body_name` | cube 的 freejoint 与 body 名 | `cube_freejoint` / `task_cube` |
| `hand_pose_by_joint` | 启动手姿态（按关节名） | 从 `model.qpos0` 自动提取 |
| `initial_red_face` | `"down"` 或 `"random"` | `"down"` |
| `cube_pos_xy_jitter` | xy 平面抖动幅度（标量或 `(x,y)`） | `0.0` |
| `max_episode_steps` | episode 步数上限 | 200 |
| `success_tolerance_rad` | 成功角度容差 | `15°` |
| `drop_height` | cube z 低于此值视为掉落 | 0.05 |

辅助方法：

- `nominal_reset_options()`：返回当前默认手姿态 + 默认 cube 位姿（四元数归一化）+ `settle_steps=0`；
- `sample_randomized_reset_options(seed, initial_red_face="random", cube_pos_xy_jitter=None)`：cube 位置加 jitter，姿态从「与 z 轴对齐的 24 个轴对齐四元数」里挑一个「红面不朝上」的（避免开局即解）；
- `reset(options=...)`：支持三种覆盖方式——`qpos / qvel` 整体覆盖，或 `hand_pose_by_joint / hand_qpos` + `cube_pos / cube_quat / cube_qvel` 细粒度覆盖。可选 `settle_steps` 让 cube 在物理上先走若干步再开始（每步 ctrl 重置成 qpos 目标，以保持手型稳定）。

### 7.4 工具脚本

`random_policy.py --env right_cube_orientation --version v2 --render-mode human` 可以直接弹出可视化，观察 cube 是否会真的被翻起来——当然随机策略成功率极低，仅用作调试。

## 8.5 手势识别 / retarget 模块（`orca_sim/retarget/`）

把摄像头或 MediaPipe 给出的 21 landmarks → sim 17 关节角的完整 pipeline。

### 模块结构

```
retarget/
├── mediapipe_hand.py        # MediaPipeHandTracker（21 landmarks 提取）
├── one_euro_filter.py       # 1€ 自适应低通滤波（ND 版用于 63 维）
├── sim_skeleton.py          # SimSkeleton：从 sim model 抽右手 17 body 解析描述
├── bone_matcher.py          # BoneMatcher：启发式初值 + LM IK 微调，替代旧 CurlSolver
├── curl_solver.py           # 旧 CurlSolver（保留为 `--use-curl` fallback）
├── ik_solver.py             # 旧 HandIKSolver（保留）
└── fingertip_helper.py      # sim 端 5 指尖世界坐标读取
```

### 用法

```python
from orca_sim.envs import OrcaHandRight
from orca_sim.retarget import SimSkeleton, BoneMatcher, BoneMatcherConfig

env = OrcaHandRight(version="v1", skin=False, render_mode="human")
env.reset(seed=42)

skel = SimSkeleton.from_model(env.unwrapped.model)
matcher = BoneMatcher(skel, BoneMatcherConfig(max_iterations=12, lm_damping=1e-3))

# 每帧：landmarks_world (21, 3) 米（已 flip X/Z 的右手世界系）
qpos = matcher.solve(landmarks_world, prev_qpos=prev_qpos, data=env.unwrapped.data)
env.step(qpos.astype(np.float32))
```

### 摄像头入口

```bash
cd orca_sim
source orca/Scripts/activate

# 默认：MediaPipe → BoneMatcher → sim
python scripts/webcam_grasp.py --render human

# 退回旧 CurlSolver（对比 / 兜底）
python scripts/webcam_grasp.py --use-curl

# 不要 LM IK 微调（只启发式，最快但精度差）
python scripts/webcam_grasp.py --no-ik

# 没摄像头时：回放预录的 5 指尖相对手腕的 .npy
python scripts/webcam_grasp.py --no-webcam --recorded-tips rec.npy
```

### 设计要点

- **SimSkeleton 不写死几何**：所有 axis / range / ref / local_pos 都从 sim model 抽——改 v2、换手型直接复用。
- **BoneMatcher = 启发式初值 + IK 微调**：启发式初值用 curl_norm + 局部 X 投影算 mcp/pip/abd；IK 微调跑 MuJoCo `mj_jacBody` + Levenberg-Marquardt 让 sim 5 指尖方向逼近 MediaPipe 5 指尖方向（**不假设距离相等**——人手比 sim 手大）。
- **Y/Z 翻转**：MediaPipeHand.from_landmarks 默认 `flip_yz=True`，因为 MediaPipe 的 `+Y` 是手背（=sim 的 `-Y`）、`+Z` 是指尖朝前（=sim 的 `-Z`）。
- **每个手指独立缩放**（针对 sim 几何 chain length）：避免单指超出 sim 可达域。
- **不偷偷热启动**：solve() 只在调用方显式传 `prev_qpos` 时才用，避免批量处理 / 测试时被上一帧污染。

## 9. 常见二次开发场景

### 9.1 换手型 / 换版本

```python
from orca_sim import OrcaHandLeftExtended
env = OrcaHandLeftExtended(version="v1")            # 显式选老硬件 + 扩展外观
```

### 9.2 替换 MJCF 自己造一个场景

1. 在 `scenes/<你的版本>/` 下新增 `scene_my_task.xml`，里面 `<include>` 一个或多个 `models/<版本>/<某只手>.mjcf`，再在 `<worldbody>` 里追加道具（例如另一个 box、目标物体）。
2. 在 `envs.py` 里继承 `BaseOrcaHandEnv`：

```python
class OrcaHandMyTask(BaseOrcaHandEnv):
    def __init__(self, render_mode=None, version=None):
        super().__init__("scene_my_task.xml", version=version,
                         frame_skip=5, render_mode=render_mode)
        # 解析自己的关节 / 道具 ID
        # ...

    def _get_reward(self):
        ...

    def _get_terminated(self):
        ...
```

3. （可选）在 `registry.py` 的 `specs` 字典里登记新的 `(entry_point, scene_file)`，再 `register_envs()` 注册一个 `env_id`。
4. 别忘了在 `pyproject.toml` 的 `package-data` 里把新加的 XML 路径加上，否则 wheel 安装后加载会找不到文件。

### 9.3 写策略的实用提示

- `env.action_low/high` 直接是 `ctrlrange`，可以直接 `np.linspace(low, high, K)` 做均匀采样。
- 想要当前 cube 状态可以直接读 `env.data` 里的 `xpos[xpos_id]`、`qpos[_cube_qpos_adr : _cube_qpos_adr+7]` 等（参考 `task_envs.py`）。
- 如果需要更密集的控制，把 `frame_skip` 调小（默认 5）；想要稳一点就调大。
- `metadata["render_fps"]=30` 是「建议渲染频率」，与物理 dt 是两码事。

## 10. 故障排查

| 症状 | 原因 / 处理 |
|---|---|
| macOS `RuntimeError: mjpython required` | 用 `mjpython` 启动 human 渲染，或改用 `rgb_array` |
| `FileNotFoundError: Unknown embodiment version` | `scenes/` 下确实没有该版本目录；检查 `list_versions()` 返回值 |
| `ValueError: Unsupported render_mode` | 只接受 `None / "human" / "rgb_array"` |
| `ValueError: Expected qpos shape ...` | `reset(options={"qpos": ...})` 必须严格匹配 `env.data.qpos.shape` |
| `ValueError: Expected action shape ...` | `step(action)` 的形状必须等于 `env.action_space.shape` |
| `ValueError: cube_pos_xy_jitter must be non-negative.` | jiterr 标量或 `(x, y)` 都不能为负 |
| 安装后 wheel 中找不到 STL | 检查 `pyproject.toml` 的 `[tool.setuptools.package-data]` 是否覆盖新加路径，重新 `pip install -e .` |

## 11. 一句话总结

`orca_sim = MuJoCo MJCF 描述的 ORCA 灵巧手（左手/右手/双手，标准/扩展，v1/v2） + Gymnasium 适配层（位置控制 action + qpos/qvel obs） + 一份 Cube Orientation 任务模板`。要把它接到 RL/IL 训练循环里，只需要构造环境 → `reset()` → 循环 `step(action)` → 用 Gymnasium 标准的 `obs/reward/term/trunc/info`；要造新任务，复制 `OrcaHandRightCubeOrientation` 的结构，往 MJCF 里加道具、改 `_get_reward/_get_terminated` 即可。

## 12. 无皮肤（`skin=False`）模式

当**还没打印 silicone 指腹 / 掌心皮肤**时，让仿真和实物一致的关键是关闭皮肤几何。`BaseOrcaHandEnv` 与所有子类、任务 env 都支持 `skin: bool = True` 参数，`view_v1.py` 暴露 `--no-skin` 旗标。

### 12.1 用法

```python
from orca_sim import OrcaHandRight, OrcaHandRightCubeOrientation

env = OrcaHandRight(version="v1", skin=False)        # 无皮肤 v1
env = OrcaHandRightCubeOrientation(version="v1", skin=False)
```

命令行：

```bash
python view_v1.py --env right --mode static --no-skin
python view_v1.py --env right_cube_orientation --version v1 --mode static --no-skin
```

### 12.2 做了什么

实现位置：[src/orca_sim/envs.py](src/orca_sim/envs.py) 的 `_disable_skin_geoms(model)`。

加载原 MJCF 之后，对每个 `geom_type == mjGEOM_MESH` 且 `mesh.name` 含 `skin`（不区分大小写）的 geom：

1. `model.geom_rgba[i, 3] = 0.0` → 视觉不可见；
2. `model.geom_contype[i] = 0`、`model.geom_conaffinity[i] = 0` → 不参与任何接触对。

`env._disabled_skin_geom_count` 记录实际被禁用的数量（v1 right 实际为 22；v2 实际为 10）。`.mjcf` / STL 资源**完全不被修改**，所以随时把 `skin=True` 切回来就恢复。

> 这个策略是「加载后置」而不是「XML 预处理」——避免在 `<include>` 相对路径上做手脚。代价是 `ngeom`/`nmesh` 数量没变，但皮肤对物理/视觉都「关掉」了，对仿真行为与打印实物一致。
